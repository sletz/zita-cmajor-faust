Port & measurement — 2 September 2026

Zita Reverb,
Cmajor versus Faust

Cmajor's ZitaReverb example, generated to C++, rewritten line by line in Faust, then both measured side by side inside one binary on an Apple M5 — with the Faust compilation options elected by fcautotool.

Approach

Four steps

01

Read the patch

The Cmajor source is a graph of five processors: an 8-branch FDN in the manner of Fons Adriaensen's zita-rev1.

02

Generate C++

cmaj generate --target=cpp emits a self-contained class of 2,147 lines.

03

Port to Faust

150 lines of Faust with the same topology, the same coefficients and the same delay-line sizes.

04

Measure

The engines take turns inside a single binary, on performance cores, minimum over 11 rounds.

Algorithm

What is in the box

Fidelity

The port is the same filter

A 96,000-frame stereo impulse response at the default settings, compared sample by sample. From frame 32 onwards the relative error between the two outputs is 1.8 × 10-7, that is -135 dB: float rounding, nothing else.

cmaj  first non-zero points : 0.0234375   0.14255272   0.14255272 ...
faust first non-zero points : 0.75        0.14255273   0.14255273 ...
                              ^ the 32-sample ramp is not ported

Only the very first sample differs: Cmajor interpolates its dry/wet levels over one 32-frame block on the first parameter change. The Faust port applies the value directly. In steady state the two signals are the same.

Election

The options decide it

fcautotool races the supported option sets against each other, then checks that the winner really reproduces the reference build's impulse response. On this DSP it elects -lang ocpp -lsum — the older C++ backend plus the recovery of the polynomial form of large sums.

  lb        10.1730 ns  (-lang ocpp -lsum)          <-- elected
  fibfu     11.3210 ns  (-lang ocpp -fir -iirt -lsum -ls-fuse -ls-sched model)
  al        14.0150 ns  (-lang ocpp -ss 8)
  ...
  cppmcd0   19.4140 ns  (-lang cpp -mcd 0)
  cppvec    21.1010 ns  (-lang cpp -vec)
  cpp       23.2110 ns  (-lang cpp)

In the A/B harness the two steps are worth: 23.8 ns for -lang cpp → 16.4 ns for -lang ocpp alone → 11.4 ns with -lsum. Picking the backend weighs more here than everything else in the comparison put together.

-lsum is marked experimental in faust -h, so its output was re-checked against the Cmajor reference: -135.1 dB with the equalisers neutral, -86.3 dB with them active — exactly the figures of the default backend.

Analysis

Where the gap comes from

Cmajor's C++ backend unrolls the graph one frame at a time

The generated advance() calls, for every frame, a main() that zeroes five intermediate IO structs, accumulates them between nodes, then enters each processor through a switch (_resumeIndex) — the translation of the language's loop / advance() coroutines. The C++ compiler cannot fuse that into a single loop.

Faust emits one fused loop

The whole graph collapses into a single loop body over flat state arrays, with the slider-dependent coefficients hoisted out of it. It is structurally the code one would write by hand.

This is not a verdict on the Cmajor language. Its native LLVM engine runs at about 22.5 ns/frame, level with Faust's -lang cpp. The gap measured here belongs to the C++ code generator, not to the Cmajor compiler — and on the Faust side too it is the choice of generator that decides, as the election above shows.

Checked in passing: the patch's predelay buffer is 19,200 words, which is not a power of two, so every sample pays two integer modulos. Forcing 32,768 buys 1.3 ns — only 3.6 %. The bulk of the gap really is structural.

Caveats

What the port does not reproduce

  • The per-block parameter ramps (dry/wet levels, reverb level): Cmajor interpolates over 32 frames after every change, the Faust port jumps straight to the value.
  • The equaliser's state machine: Cmajor switches between bypass, static and smooth, and computes nothing at all when the gain is 0 dB. Faust always computes the section.
  • Faust recomputes the eight filters' pow and sqrt on every compute() call; Cmajor only when a parameter moved. Invisible here — the cost measured the same from 32 to 1,024 frames per block.
  • Both versions are limited by the fixed line size of 16,384: above roughly 64 kHz, the longest delay of the original Cmajor patch no longer fits in its buffer.

The first three are control-rate matters: they change nothing in steady state, which the -135 dB confirms, but they do change what happens while a knob is moving.

Method

How this is measured

One binary holds every implementation. A round processes 10 seconds of identical noise per engine, the engines alternating inside the round so that thermal drift and frequency scaling hit all of them equally; the minimum over 11 rounds is kept, the first round being warm-up. The thread runs at QOS_CLASS_USER_INTERACTIVE to stay on the performance cores.

Apple M5 · Darwin 25.6.0 · Apple clang 21.0.0
clang++ -std=c++17 -O3 -mcpu=apple-m4        (identical on both sides)
  (with -ffast-math throughout: 35.1 / 23.6 / 11.0 - the ratios do not move)
Cmajor 1.0.3177   ·   Faust 2.87.11
48 kHz · block of 512 · single-precision float

State footprint: 1.21 MB for Cmajor, 1.39 MB for the generic Faust port, 0.45 MB for the fixed-rate variant — Faust then sizes its tables on the delays actually requested instead of the declared maximum.
